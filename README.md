# PathSnap

Distributed map matching and route reconstruction for PES UE24CS352A.

## Current implementation status

This checkout contains the raw train and reserved student-test trips, inventory and feature-generation code, a logistic-regression baseline, shared metrics, FastAPI endpoints, and a Streamlit frontend. The frontend consumes the documented API response and never retains reference labels or reference-route geometry. It reads model-comparison rows from actual `results/experiments.csv` output.

The final HMM/Viterbi decoder, five-model comparison, Bayesian search, trained model bundle, and comparison outputs are not present in this checkout yet. The UI can show only results generated by components that are delivered and run; it shows an empty state when comparison data is unavailable. See [the report outline](docs/report_outline.md) for the evidence required before submission.

## Requirements and data

- Ubuntu or another Linux environment with Python 3.10+.
- Dataset root containing `train/` and `student_test/`. The current checkout has these folders in the repository root.
- A trained bundle at `artifacts/model_bundle.joblib` before `/predict` can serve predictions.
- Install the application requirements in a virtual environment:

```bash
cd ~/projects/PathSnap
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export PATHSNAP_DATA_DIR="$PWD"
```

`PATHSNAP_DATA_DIR` can point to a different dataset root. Without it, PathSnap searches `<repo>/data`, the repository root, then the team's local materials fallback.

## Start on one laptop

With a compatible trained model bundle present:

```bash
export PATHSNAP_DATA_DIR="$PWD"
bash scripts/run_all.sh
```

Open `http://localhost:8501`. The combined script starts the API on `127.0.0.1:8000`, checks `/health`, then starts Streamlit. Ctrl+C stops the services.

## Start on two laptops

On Laptop 1, which has the dataset and model bundle:

```bash
export PATHSNAP_DATA_DIR="$PWD"
export PATHSNAP_API_HOST=0.0.0.0
export PATHSNAP_API_PORT=8000
bash scripts/run_api.sh
```

On Laptop 2, set Laptop 1's private LAN address:

```bash
export PATHSNAP_API_URL=http://<LAPTOP_1_PRIVATE_IP>:8000
bash scripts/run_ui.sh
```

Open `http://localhost:8501` on Laptop 2. Allow inbound TCP 8000 on Laptop 1 for the trusted local network if required by its firewall. Keep the API off public networks. The UI's sidebar checks `/health` and reports API connectivity. Full instructions and a demo sequence are in [docs/demo.md](docs/demo.md).

## API contract

- `GET /health` returns service and model status.
- `GET /trips` returns the available trip IDs.
- `POST /predict` accepts `{"trip_id":"00000056"}` and returns observations, predicted route geometry, aggregate metrics, and timings.

Reference labels and reference geometry stay on the server. For details see [docs/contracts.md](docs/contracts.md).

## Data and model build

`scripts/run_phase1.sh` runs inventory, feature generation, baseline training, and an offline map. It is a build command and can replace generated feature files and the baseline artifact; it also appends a row to `results/experiments.csv`. Do not run it over existing artifacts you need to preserve. The per-step commands are in the script headers and `PathSnap_Team_Plan.md`.

## Tests

Run the available unit and API contract tests with:

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

The API contract tests need the application dependencies from `requirements.txt`. They are skipped when dependencies are missing. `python3 -m compileall -q src tests` and `bash -n scripts/run_api.sh scripts/run_ui.sh scripts/run_all.sh` provide syntax checks.
